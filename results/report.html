Conclusión

La configuración original (--spec-draft-ngl 0, draft model en CPU) es la peor de las tres opciones — entre 41% y 54% más lenta que no usar MTP en absoluto. El costo de mover datos entre CPU y GPU para verificar cada token especulativo supera cualquier ahorro.

Moviendo el draft también a GPU (--spec-draft-ngl 999) se recupera la mayor parte del rendimiento perdido, e incluso supera al caso sin MTP en generación de código (26.3 vs 23.7 tok/s), pero pierde en los otros dos prompts. En este hardware — 2× RTX 3060 con un draft model MTP relativamente costoso de verificar — el speculative decoding no rinde de forma consistente.

Recomendación: para uso general, correr sin MTP (~28 tok/s estables). Activar MTP con --spec-draft-ngl 999 solo si la carga es predominantemente generación de código o texto muy predecible, donde la tasa de aceptación del draft es más alta.
